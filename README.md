# 星帷塔罗

以对话为线索的塔罗应用。紫色夜空、三维抽牌仪式、完整 78 张维特牌面、可翻看的逐牌解析；管理端负责账号、模型与 Token 用量。支持手机和电脑横竖屏、本地运行及单实例 Docker 部署。

项目仓库：[someone97421/tarot-master](https://github.com/someone97421/tarot-master)。用户端入口为 `/`，管理端入口为 `/#/admin`；模型配置仅对管理员开放。

技术栈：React、TypeScript、Vite、CSS 3D、FastAPI、SQLite。模型接口支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages。

## 已实现功能

- 登录后进入新祈愿，首次发送才保存会话；历史对话及其抽牌结果长期保留。
- 历史列表支持手动删除对话，关联消息、牌阵和未被其他对话引用的图片一起清理，累计用量保留。
- 根据祈求设计牌阵和牌数，先呈现浪漫开场及牌位职责，再开启抽牌。
- 后端系统随机抽牌，单次不重复，默认含正逆位；重复揭牌请求返回原结果。
- 78 张连续展牌，打开后自动洗牌 3 秒；触摸滑动、鼠标拖动及滚轮横向浏览，明确点击即抽牌并居中翻牌，已抽轨迹可回看。固定舞台适配横竖屏，支持跳过仪式和减少动态效果。
- 牌面放大和翻看、桌面解析表格、移动端逐牌卡片、整体叙事与行动建议。
- 普通聊天与排阵开场逐步输出；解读在最终卡片、表格、综合解读、行动列表和结语版式内流式填充，完整结构校验后保存，不重复追加正文。
- JPEG、PNG、WebP 图片上传与模型理解，每条消息最多 4 张、单张最多 10 MB。图片自动校正方向、缩至最大 2048 像素并转为 JPEG，存储和访问按账号隔离。
- 账号卡片管理：新增、编辑、删除、启停、密码重设、管理员与普通用户角色。
- 模型配置：接入点、Model ID、API Key、Schema、思考级别、图片能力、上下文窗口、压缩阈值、最大输出 Token、默认模型与连接检查。用户端统一使用默认模型。
- 普通聊天、排阵和解读均支持流式展示；模型返回的思考内容默认折叠，可展开观测，并随已完成消息保存。
- 输入／输出／缓存 Token、缓存命中率，按日期、账号、模型筛选；包括排阵、解读、聊天、摘要压缩与连接检查。

## 获取源码

```sh
git clone https://github.com/someone97421/tarot-master.git
cd tarot-master
```

仓库包含源码、依赖锁文件和完整牌面素材。运行时数据库、用户上传、模型密钥、依赖目录及前端构建产物不纳入版本控制；从仓库克隆后，按下方步骤构建或使用 Docker。

## Docker 运行

需要 Docker Engine／Docker Desktop 及 Compose 插件。在项目根目录执行：

```sh
docker compose up --build
```

浏览器访问 `http://localhost:8000`。同一局域网的手机访问 `http://电脑的局域网IP:8000`。首次打开页面创建管理员，然后从管理入口添加模型并设为默认，即可开始对话。

命令保持前台运行，按 Ctrl+C 停止。需要移除容器时执行 `docker compose down`，主机 `data/` 目录仍保留。

若修改端口，将 `.env.example` 复制为 `.env`，修改 `TAROT_PORT`。HTTPS 反向代理部署时，可将 `TAROT_COOKIE_SECURE` 设为 `true`；普通本地 HTTP 保持 `false`。

容器访问宿主机模型服务时，Docker Desktop 通常使用 `host.docker.internal`，例如 `http://host.docker.internal:11434/v1`。Linux 按实际网络配置宿主机地址。模型接入点应指向容器能访问的地址。

## 本地运行

准备 Python 3.11 或以上版本与 Node.js 22.12 或以上版本。以下命令在项目根目录执行。

Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm.cmd --prefix web ci
npm.cmd --prefix web run build
.\.venv\Scripts\python.exe -m uvicorn server.main:app --host 0.0.0.0 --port 8000 --workers 1
```

macOS／Linux：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm --prefix web ci
npm --prefix web run build
.venv/bin/python -m uvicorn server.main:app --host 0.0.0.0 --port 8000 --workers 1
```

访问 `http://localhost:8000`。后端统一提供 H5 页面和 API，不需要另行部署 Web 服务器。运行命令保持在独立、可见终端中，按 Ctrl+C 停止；不使用后台启动参数。

开发前端时，保持后端终端运行，在第二个终端执行 `npm --prefix web run dev`（Windows 可用 `npm.cmd`），访问 Vite 显示的地址。开发代理把 `/api` 请求发送至 `127.0.0.1:8000`。使用开发地址登录后在同一地址继续使用，Cookie 会话属于相应主机。

## 首次使用

1. 首次访问创建管理员账号，系统没有内置通用密码。
2. 进入管理界面的模型配置，选择接入服务预设或自定义地址，填入实际可用的 Model ID 与 API Key。
3. Schema 默认选择 `Chat Completions`；按服务实际接口改为 `Responses` 或 `Anthropic Messages`。
4. 设置上下文窗口、最大输出长度及压缩阈值；首版默认 128000／8192／75%，请依据实际模型修改。
5. 需要看图时启用图片能力，并确认该 Model ID 本身支持图片。
6. 保存后运行连接检查，设置为默认模型。连接检查是一次真实文本请求，会产生用量，不代替图片能力验证。
7. 通过账号卡片创建用户。用户登录后即可对话，没有模型选择或配置入口。

接入点填写 API 前缀，例如含 `/v1` 的地址；也接受末尾为 `/chat/completions`、`/responses` 或 `/messages` 的完整端点，后端会归一化。接入服务、模型 ID 与支持能力会随服务商变化，预设仅辅助填写，最终以服务商文档和实际账号权限为准。

`none` 思考级别表示不发送额外思考参数，使用服务默认行为；不等同于强制关闭模型的内置思考。预置支持 `low`、`medium`、`high`、`xhigh`、`max`，也可选择自定义级别值和点分请求字段（例如 `reasoning.effort`、`output_config.effort`）。不设置自定义字段时，Chat Completions／Responses 使用各自的标准字段，Anthropic 映射为扩展思考预算并预留正文输出空间；填写自定义字段后直接向该字段传入级别值。实际支持的级别取决于模型和接入服务。思考观测只展示接口实际返回的内容，不返回思考的模型不会产生该记录。图片能力开关只控制应用是否发送图片，不会改变模型本身的能力。

## 对话、抽牌与恢复

参考 `塔罗大师.zip` 的流程：情绪承接 → 牌阵设计 → 程序随机抽牌 → 逐牌解读 → 牌际关联 → 行动建议。普通追问和反馈不必抽牌；补牌用于澄清缺口。

大牌阵会按模型输出预算分批生成逐牌解析，再总结整组关系。页面显示当前进度；每一批和整体总结均计入用量。中断后保留固定牌面，重新解读可能重复产生已完成批次的模型调用费用。

每次抽牌保存三个阶段：待开启、已抽取、已解读。牌面在揭示请求中固定并持久化，动画只展示这一结果。关闭仪式、刷新页面、网络中断后，都可以从历史对话继续查看或继续解读。解读请求重试不会更换牌。单次调用无重复；不同抽牌和补牌之间允许再次出现同一张牌，与参考 skill 一致。

解析结构会校验牌数、牌 ID 和顺序；不合法时最多自动重新请求一次。重试也计入 Token 统计。模型正文的准确性仍取决于所配置模型，后端不能保证其每句自然语言都与牌意一致。

自动压缩依据估算的输入长度和预留输出预算触发。原始聊天、图片引用与完整牌阵永远留在数据库；模型接收历史摘要与近期消息，另外附带最近三次牌阵的固定事实。摘要生成也使用管理员指定模型并统计用量。较早图片压缩后保留已识别内容的文字摘要，原图仍可在历史消息中查看。

## 用量口径

- 优先保存服务实际返回的 input/output usage；没有完整 usage 时按文本长度和图片数量估算，并在管理端标记估算请求。
- 输入 Token 包含其中已命中的缓存 Token，不能再次相加。
- Anthropic 输入统计会加上 cache creation 与 cache read，归一为总输入。
- 缓存命中率 = 已报告缓存数据且用量完整的请求中，缓存命中输入 Token 之和 ÷ 总输入 Token 之和。
- 没有缓存字段时命中率显示「未提供」，不视为 0%。混合服务筛选时只用有完整缓存数据的请求计算此比例。
- 当前页面展示最近 100 条调用明细，汇总统计覆盖筛选范围。日期按 UTC 汇总。
- 失败前模型已经接收的流式请求也可能计费；有返回 usage 则保存实际值，否则记为估算。HTTP 直接拒绝的请求不计入成功接收用量。

## 数据与备份

默认持久化目录 `data/` 包含：

| 文件／目录 | 内容 |
|---|---|
| `tarot.sqlite3` | 账号、模型配置、消息、牌阵、摘要、用量 |
| `secret.key` | 模型 API Key 的本地加密密钥 |
| `uploads/` | 用户上传并归一化的图片 |

备份时先停止应用，再复制完整 `data/` 目录；恢复时将完整目录放回原处。数据库和 `secret.key` 需要一起迁移，否则原有模型 Key 无法解密。Docker 挂载 `./data:/app/data`，本地可通过 `TAROT_DATA_DIR` 环境变量更改路径。

账号删除会同时删除该账号的会话、牌阵与上传文件；已累计的用量保留账号名称快照。停用账号可保留全部资料。当前登录的管理员不能直接删除、停用或降权自身，可用另一管理员账号管理。

目前使用 SQLite 和进程内会话互斥，按单实例、单 worker 部署；不要用多个应用进程共用同一数据目录。反向代理需要关闭 SSE 响应缓冲，并给较长的模型响应预留超时时间。API 流每 15 秒发送心跳。
