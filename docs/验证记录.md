# 首版验证记录

本轮使用隔离数据目录和模拟模型响应进行验证，没有调用真实付费模型，也没有向交付目录写入测试账号或模型 Key。

## 已执行并通过

- 后端 11 个 Python 文件的静态语法解析；关键后端逻辑另经一次独立只读审查。
- 前端 `tsc -b && vite build` 生产构建，构建结果位于 `web/dist/`，前端依赖锁文件位于 `web/package-lock.json`。
- 隔离后端冒烟检查通过 55 项断言（包含请求状态和终止事件等重复基础断言）：
  - 首次管理员初始化及重复初始化拦截。
  - 账号编辑、空白密码保持原值、删除后会话失效。
  - 普通用户无法读取管理配置；对话与图片跨账号访问被拒绝。
  - 图片上传与读取，模型 Key 不回显。
  - 单次随机抽牌无重复、重复揭牌保持相同结果、解析牌序一致。
  - 重放已完成解析不再次调用模型。
  - 普通追问流式输出且不创建新牌阵。
  - 三种协议使用模拟 SSE 验证，包括末尾无空行、空 delta、缓存用量归一化。
  - 七张牌阵分批解读与整体总结。
  - 上下文压缩产生摘要和进度，原始消息保留。
  - 响应正文开始前断线时会话忙碌标记释放。
- Chromium 浏览器实际操作：登录后空白新对话、发送祈求、三维扇形牌堆、三张牌逐张揭示、解析展示、牌面放大及上一张／下一张和左右方向键。
- 管理端账号卡片、模型列表、Token 统计页面渲染，手机管理页宽度检查。
- 历史会话恢复及既有牌面读取。
- 1440×1000、390×844、844×390 三种视口的页面宽度检查；手机使用逐牌卡片，横屏采用缩略牌面和紧凑输入区。
- 横屏仪式按钮位置检查：在 844×390 视口中，按钮底边为 350px，没有被裁切。
- 78 张牌图与 manifest 条目完整，编号与后端牌库一致，来源许可逐项记录。

构建中存在 Three.js 所在主包超过 500 kB 的体积提示，构建成功；当前主 JS 压缩前约 701 kB、gzip 后约 192 kB。

## 尚未验证

- 当前环境没有 Docker 命令，未执行 Docker 镜像构建或容器运行；Dockerfile、Compose 与路径配置已静态核对。
- 未提供实际服务商配置，真实模型的鉴权、图片理解质量、思考级别支持和真实缓存策略仍需配置后联调。后台连接检查是一次真实文本请求。
- 浏览器检查使用桌面 Chromium 的视口模拟，没有在真实 iPhone／Android 手机或 Safari 中运行。
- 未做全量并发、压力、长时间运行及每一张牌图的逐页人工视觉检查。

临时验证服务在检查结束后停止。交付应用首次启动仍需创建自己的管理员并配置默认模型。
