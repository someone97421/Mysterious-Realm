# 双人关系分析

## 业务目标及触发条件

围绕明确的双人关系目标，分析双方需要如何互动、哪些领域易协调或出现张力。适用于用户明确要求双人比较或组合盘解读；先确认关系性质、阶段和双方已知立场，不预设关系必须延续，也不输出契合度判决。

## 所需信息与缺失处理

需要双方分别可识别的出生日期、地点、时间及可信程度，还有本次关注的互动领域。仅收集分析必需资料，不要求真实姓名或无关隐私。只有一方资料时转回个人探索。任一方时间缺失时，不解释其宫位、上升、精确月亮及时间事件；不解释受影响的落宫、轴点联系和组合盘敏感结构。另一方资料完整不能补齐缺失，无法确认稳定性的指标应排除。

## 专业分析维度和执行方法

依照 [关系知识](../../references/relationships.md)、[核心知识](../../references/core.md) 与 [交流原则](../../references/communication.md)。

1. 分别整理双方本命的情绪、价值、沟通、行动及界限需要，避免一开始只看跨盘相位。
2. 通过双人比较盘评估个人行星之间的主要联系，再结合可靠轴点和落宫，说明可能的互动机制与调节条件。
3. 同时保留支持与摩擦；不按相位数量计分，不将流畅等同健康或将紧张等同有害。
4. 双方资料充分且用户关注关系整体时，可补充组合盘，明确其为中点形成的象征结构，不与双方个人需要混为一谈。
5. 分开标注个人本命、比较盘和组合盘的依据，结合现实互动反馈，不将多盘重复主题冒充独立验证。

## 可调用 Tools

- `geocode`：分别核实双方出生地点。
- `natal-chart`：取得双方各自的本命背景。
- `synastry`：取得双人比较资料。
- `composite-chart`：在资料充分时补充关系整体结构。
- `render-chart`：按需可视化已取得的对应盘面。
- `provider-usage`：仅用于用户询问额度或调用前成本核查。

## 条件分支

资料完整时可综合三类盘；一方时间未知时仅保留可靠的跨盘行星信息，并说明排除项。只有个人恋爱困惑时转回个人情感流程。用户要求判断他人隐秘动机、忠诚或给确定分合日期时，收窄为可证实的事实和自主选择；出生时间不全时不推断个人事件日期。工具失败时停止对应层的分析，不用其他盘伪造缺失结果。

## 多 Skill 协作

个人情感需要交给 [love-consultation](../love-consultation/SKILL.md)，长期节奏交给 [annual-forecast](../annual-forecast/SKILL.md)，候选时间比较交给 [event-timing](../event-timing/SKILL.md)。移交双方资料的独立可信程度、关系目标、已取得结果与限制；不得因协作模糊个人盘和关系盘的边界。

## 中断退出恢复

用户停止或不愿继续涉及另一人的内容时立即暂停。记录双方资料分别的可靠性、已完成盘种、尚缺结果与目标，恢复时先核对关系状态及资料变化。只复用仍有效的结果，资料修正时重审直接受影响的关系判断，不把旧互动结论当作持续事实。

## 不确定性与输出原则

关系占星是象征性探索，不是科学验证的适配或事件预测。输出依据、分歧、可讨论的需要及界限，不替双方决定关系，不制造恐惧或确定命运。现实同意、安全和行为优先，医疗、法律、财务与心理问题不替代专业意见。自然交流，不加入人物案例、故事、示范对话、固定话术或预设回答。
