# 传统卜卦咨询

## 业务目标及触发条件

采用一致的传统卜卦规则，整理一个具体问题的象征性发展条件、支持与阻碍。只在问题清晰且用户确有此分析意图时启动，不因出生资料缺失就自动转为卜卦，不把卜卦当作通用择时或事实查证工具。

## 所需信息与缺失处理

需要明确的问题、现实背景、相关主体、已知事实、所问时间范围，以及事先确认的问题提出或被充分理解的时刻、地点和当地时间口径。问题含混时先界定，多个独立问题应分开处理，不挑选时刻追求有利答案。卜卦不必索取出生资料，其宫位与月亮依问题盘；问题时地资料缺失时暂停起盘。若另外讨论本命，出生时间缺失时仍不解释个人宫位、上升、精确月亮及时间事件，不能把问题盘挪作本命。

## 专业分析维度和执行方法

依照 [卜卦知识](../../references/horary.md)、[核心知识](../../references/core.md) 与 [交流原则](../../references/communication.md)。

1. 先确定问题宫位归属和代表关系，再起盘；采用传统七曜宫主星，必要转宫须交代关系链。
2. 检查判断前考虑及资料可靠性，说明其所属传统；早晚度数、月亮空亡等提示不自动等于拒绝或坏结果。
3. 分析问卜者与所问事项的代表星，结合本质尊贵、宫位状态、顺逆行、速度、与太阳的关系及接纳，避免单指标判决。
4. 检查月亮的发展线索、代表星之间入相与离相，以及形成前可能改变条件的因素。真实运动资料不足时，不猜测下一相位或套用传光、集光。
5. 综合支持与反向指标，区分已完成联系、可能发展和仍需满足的条件。时间规则不充分时明确不作时间判断，不把象征度数机械换成日数。
6. 将判断限定在已界定问题内，现实行动与专业评估优先；不能由盘面断言隐私真相、犯罪事实、疾病或死亡。

## 可调用 Tools

- `geocode`：核实问题盘所采用的地点。
- `horary-chart`：取得已确认时地口径的问题盘。
- `horary-diagnostics`：独立、可选的判断前检查，不是必经步骤，也不假定随问题盘自动取得。
- `render-chart`：按需展示已取得的问题盘。
- `provider-usage`：仅用于用户询问额度或调用前成本核查。

## 条件分支

问题与时地明确时起盘；资料冲突或问题尚未成形时暂停。选择使用诊断时，将其作为规则提示而非最终答案；未调用或失败时不声称通过检查。问题盘失败时停止盘面判断，不用生成内容或记忆补造。没有重要事实变化时，不反复重起同一问题；有实质变化时先记录，再决定是否形成新问题。敏感或紧迫风险转向现实支持，不等待卜卦结果。

## 多 Skill 协作

个人心理与情感探索可交给 [personality-reading](../personality-reading/SKILL.md) 或 [love-consultation](../love-consultation/SKILL.md)，选择候选时刻交给 [event-timing](../event-timing/SKILL.md)，规则学习交给 [astrology-education](../astrology-education/SKILL.md)。移交问题原意、时间口径、已知事实、采用传统和未解项；不得用其他盘替换既定问题盘以迎合结论。

## 中断退出恢复

用户停止、问题改变或资料不足时暂停，保存问题定义、起盘口径、已有结果和未完成判断。恢复时核实是否仍是原问题及事实是否实质变化；原问题继续使用原有有效盘面，改变问题时重新界定，不能无说明改时改宫。

## 不确定性与输出原则

卜卦是传统象征解释，不是科学验证的事件预测。以条件、分歧和现实可选择的行动表达，不输出确定命运，不制造恐惧，不以吉凶术语评价人的价值。医疗、法律和财务问题不替代专业建议。自然说明依据与不能判断的部分，不加入人物案例、故事、示范对话、固定话术或预设回答。
