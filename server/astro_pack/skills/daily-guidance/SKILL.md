# 每日与短期指引

## 业务目标及触发条件

围绕目标日期的注意力、节奏和自我观察提供简明辅助。适用于每日或短期指引、个人行运关注与通用天象说明。先明确用户要个人化分析还是一般内容，不默认两者具有相同证据基础。

## 所需信息与缺失处理

需要目标日期、所在地或所采用的时区、关注领域与希望的内容性质。个人分析另需出生日期、地点、时间及可信程度，或已核实的本命结果。目标日期或当地时间口径不明时先核实。出生时间缺失时，不解释宫位、上升、精确月亮及时间事件，暂停个人每日行运判断；可转为明确标注的通用天象或一般反思，不能称为个人计算。不得假定用户的情绪、安排或当天经历。

## 专业分析维度和执行方法

依据 [时间知识](../../references/timing.md)、[核心知识](../../references/core.md) 与 [交流原则](../../references/communication.md)。

1. 核实日期边界和分析范围，避免把其他时区的日期直接当作用户的当天。
2. 个人资料充分时，以本命为背景读取个人行运，筛选与用户目标直接相关的主要联系，区分长期背景与短期节奏。
3. 需要观察数日过程时使用个人行运日历，保留接近、精确、离开及重复接触的连续性，不把每个日期写成独立命运事件。
4. 通用模式下区分天象资料与生成内容；通用天象不能自动推导个人反应，生成内容不能充当个人行运依据。
5. 将象征主题整理为可自主选择的观察与安排方向，现实日程、身体感受与专业要求优先。

## 可调用 Tools

- `geocode`：在需要时核实出生地或目标地点。
- `natal-chart`：建立或复用可靠的个人本命基础。
- `transits`：取得目标时段的个人行运。
- `transit-calendar`：按需组织短期个人行运过程。
- `sky-event-kinds`、`sky-events`：了解天象类别并取得通用天象。
- `horoscope`、`astro-content`：仅提供明确标注的通用生成内容，不作个人计算。
- `render-chart`：按需展示已有可靠盘面。
- `provider-usage`：仅用于用户询问额度或调用前成本核查。

## 条件分支

个人资料完整时走个人行运；资料不足或用户只要一般内容时明确转为通用模式。若目标是年度结构或比较候选时间，分别转交对应业务。工具失败时说明未取得哪类资料，停止其依赖判断；不能把生成内容伪装为失败的个人行运结果。出现健康、法律或交易指令诉求时，停止占星式指令并指向现实判断与专业支持。

## 多 Skill 协作

长期节奏交给 [annual-forecast](../annual-forecast/SKILL.md)，具体候选比较交给 [event-timing](../event-timing/SKILL.md)，理解概念可联动 [astrology-education](../astrology-education/SKILL.md)。移交目标日期、时间口径、个人资料精度、已取得结果及通用或个人模式，保持来源性质清楚。

## 中断退出恢复

用户停止时立即结束；资料不全或工具失败时保留已完成部分及待补信息。恢复时先核实目标日期是否仍有效，日期变更应重新确认直接依赖的行运资料，不能沿用旧日提示。个人与通用模式发生切换时，重新声明分析范围。

## 不确定性与输出原则

每日指引属于象征性反思，不是科学验证的事件预测。不得断言当天必然发生的遭遇、情绪、灾祸或收益，不制造恐惧和依赖。医疗、法律和财务问题不替代专业建议。说明资料与解释的层次，用自然交流控制篇幅，不加入人物案例、故事、示范对话、固定话术或预设回答。
