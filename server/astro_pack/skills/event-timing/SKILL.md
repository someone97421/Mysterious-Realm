# 事件候选时间比较

## 业务目标及触发条件

在实际可行的候选时间中整理象征性侧重与取舍，辅助用户安排。适用于已经明确目标、地点、时间范围和现实限制的择时；区分选择将来时刻、个人行运观察与询问事情走向，不以择时替代后两者。

## 所需信息与缺失处理

需要事件目标、地点、可行日期与时刻范围、当地时间口径、不可更改条件及用户优先级。信息不足时先确定候选范围，不凭空生成场地、时间或承诺。候选时刻不明确时，不解释其宫位、上升或精细时间窗口。若需联系个人本命，另需可靠出生资料；出生时间缺失时，不解释个人宫位、上升、精确月亮及时间事件。具备自身完整时地资料的事件盘可独立比较，但不得据此补齐个人资料或宣称个人事件预测。

## 专业分析维度和执行方法

依据 [时间知识](../../references/timing.md)、[核心知识](../../references/core.md) 与 [交流原则](../../references/communication.md)。

1. 先排除现实不可行、违背专业安排或无法满足必要条件的时间，明确实际开始时刻的定义，避免更换定义迎合盘面。
2. 通用择时使用 `natal-chart` 取得各候选时刻的事件盘；明确此处读的是候选事件时刻，而非某个人的出生盘。
3. 在一致的解释传统下比较与目标相关的宫位、宫主星、角点、月亮状态、主要相位、入相离相及接纳；缺少运动资料时不推断后续相位。
4. 商业启动日可用 `electional-day` 辅助日期筛选；仍须按所需精度比较候选事件盘，日期层面的结果不能直接变成分钟级结论。
5. 若明确要求个人适配且出生资料充分，可参考个人行运作为独立层次；不能将事件盘、个人行运和日期辅助混作同一证据。
6. 列明候选间的支持、限制和取舍；不存在全面完美的时刻，不把排序写成科学概率或成功保证。

## 可调用 Tools

- `geocode`：核实事件地点，以及确需个人分析时的出生地点。
- `natal-chart`：比较候选事件时刻盘面；个人本命须另行标识，不能混用。
- `electional-day`：仅辅助商业启动日的日期筛选。
- `transits`、`transit-calendar`：仅在个人资料充分且目标需要时，补充个人行运背景。
- `render-chart`：按需展示已取得的候选盘面。
- `provider-usage`：仅用于用户询问额度或调用前成本核查。

## 条件分支

通用择时走候选事件盘比较，不将 `electional-day` 用于其他领域。候选范围过宽时先与用户收敛现实可行范围，再按所需精度分阶段比较，不能虚称已穷尽全部时刻。工具失败时保留未比较项，不推选没有依据的最佳时间。涉及医疗操作、法律期限或金融交易时，专业安排和现实责任优先，不以占星推迟必要处置或给交易指令。

## 多 Skill 协作

年度个人背景可联动 [annual-forecast](../annual-forecast/SKILL.md)，商业目标可联动 [career-consultation](../career-consultation/SKILL.md)，明确的问题走向可转交 [horary-consultation](../horary-consultation/SKILL.md)。移交目标、时间定义、地点、候选范围、优先级、资料精度与已有结果；不能以卜卦替换候选盘比较。

## 中断退出恢复

用户停止或候选条件变化时暂停，保存已核实限制、比较过的候选、资料来源和未完成项。恢复时先确认候选仍可用、时间窗口尚未失效、地点和开始定义未变；变化时只更新受影响比较，不继续推荐已失效时刻。

## 不确定性与输出原则

择时提供象征性决策辅助，不是科学验证的事件预测。只说明比较范围内的侧重，不宣称最佳命运、消除风险或必然成功，不制造错过时刻即遭厄运的恐惧。医疗、法律和财务问题不替代专业建议。自然呈现依据、资料精度与取舍，不加入人物案例、故事、示范对话、固定话术或预设回答。
